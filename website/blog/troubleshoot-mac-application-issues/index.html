How to Troubleshoot Common Mac Application Issues

By Aditya Gupta • Published on November 8, 2026 • Diagnostics • 6 min read

When a macOS application freezes, fails to launch, or misbehaves with permissions, users often resort to random restarts or reinstallations. However, macOS provides an exceptional suite of diagnostic tools that allow you to isolate and resolve software problems methodically.

In this guide, we outline a four-step diagnostic workflow used by experienced macOS administrators and developers.

Step 1: Inspect Activity Monitor for Deadlocks

When an app appears unresponsive, open Activity Monitor (via Spotlight or /Applications/Utilities):

  • CPU Tab: Look for processes marked in red as Not Responding. A process consuming 100% of a CPU core typically indicates an infinite loop.
  • Sample Process: Select the unresponsive app, click the Gear icon > Sample Process. The resulting stack trace highlights exactly which function call is blocking the main dispatch queue.

Step 2: Stream Live Logs with the Console App

The macOS unified logging system (os_log) captures diagnostic messages, assertion failures, and permission rejections across the entire operating system.

To inspect live application logs in Terminal: 

# Stream live logs filtered by subsystem or process name
log stream --predicate 'process == "NotchFlow"' --level debug

If an application fails to capture microphone audio or load a document, the log stream will report the specific OSStatus or NSError code explaining why.

Step 3: Diagnose Permission and Privacy Rejections

A frequent source of modern application issues is mismatched or corrupted TCC privacy entries. If an app fails to access your microphone or disk:

  1. Check System Settings > Privacy & Security to verify that permissions are enabled.
  2. If the permission toggle appears stuck or fails to take effect, reset the application's permission record: 
    tccutil reset Microphone com.adityagupta.notchflow
  3. Relaunch the app to trigger a clean authorization dialogue.

Step 4: Clear Corrupted User Defaults & Caches

Most macOS applications store window positions, theme preferences, and state in the user defaults system (~/Library/Preferences/). If an app crashes immediately upon opening due to corrupted window coordinates: 

# Delete application preference domain
defaults delete com.adityagupta.notchflow

# Clear application container cache
rm -rf ~/Library/Caches/com.adityagupta.notchflow

Conclusion

Systematic troubleshooting transforms software frustration into a clear diagnostic exercise. By leveraging Activity Monitor, log stream, and tccutil, you can resolve macOS application issues quickly and effectively.
