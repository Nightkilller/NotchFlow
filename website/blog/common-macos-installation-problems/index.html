Common macOS Application Installation Problems and Their Solutions

By Aditya Gupta • Published on November 7, 2026 • Troubleshooting • 6 min read

Installing software outside the official Mac App Store offers immense flexibility, especially for open-source tools and developer utilities. However, Apple's multi-layered security protections—including Gatekeeper, Notarization, and extended quarantine attributes—can occasionally trigger confusing error messages.

In this practical guide, we examine the most common macOS application installation hurdles and provide step-by-step solutions to resolve them.

1. “App is damaged and can't be opened”

Cause: When you download an application using Safari or Chrome, macOS attaches an extended filesystem attribute (com.apple.quarantine) to the file. If an open-source application has not undergone Apple's paid notarization ticket stapling, Gatekeeper displays an alarming “damaged” dialogue. The application is almost certainly not damaged; macOS is simply preventing unverified execution.

Solution: You can clear the quarantine attribute using Terminal:

# Strip quarantine attribute from the installed application
xattr -cr /Applications/NotchFlow.app

The -c flag clears all extended attributes, while -r applies the command recursively across the entire bundle.

2. “Cannot be opened because the developer cannot be verified”

Cause: Gatekeeper allows downloads from verified App Store developers by default, while flagging community open-source projects.

Solution: You do not need to disable system security entirely to open a trusted app:

  1. Open System Settings > Privacy & Security.
  2. Scroll down to the Security section.
  3. Locate the notification stating that the app was blocked, and click Open Anyway.
  4. Enter your Mac administrator password or use Touch ID to confirm.

Pro Tip: You can also right-click (or Control-click) the application in Finder and select Open from the contextual menu. This triggers an override dialogue with an explicit “Open” button.

3. “You do not have permission to open the application”

Cause: This error typically arises when executable permissions (+x) are lost during an archive extraction or when an application binary compiled for Apple Silicon is executed on an older Intel Mac (or vice-versa).

Solution: Restore executable file permissions via terminal:

chmod +x /Applications/NotchFlow.app/Contents/MacOS/*

Also confirm your hardware architecture using uname -m. NotchFlow is built natively for arm64 (Apple Silicon).

4. Read-Only Disk Image Execution

Cause: Users sometimes launch applications directly from inside the mounted .dmg file instead of dragging them to the local drive. Running from a read-only disk image prevents the app from saving preferences, updating itself, or loading dependent resources properly.

Solution: Always drag NotchFlow.app into /Applications before launching. Eject the disk image afterward.

Conclusion

Navigating macOS security controls requires understanding the difference between genuine malware warnings and standard Gatekeeper checks for independent open-source software. By mastering the xattr and chmod commands, you can manage your Mac applications cleanly and safely.
